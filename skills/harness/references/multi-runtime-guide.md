## 1. 왜 멀티런타임인가 — 그리고 언제 쓰지 말아야 하는가

기본 하네스의 팀원은 전부 Claude Code 인스턴스다. 팀원이 다섯이든 일곱이든 **모델 계열이 하나**라, 서로 교차 검증을 해도 같은 모델의 같은 맹점을 공유한다. 한 모델이 놓치는 것은 그 모델의 다른 인스턴스도 대체로 놓친다.

멀티런타임의 유일한 실질 가치는 **모델 다양성**이다. "어느 CLI가 더 우수한가"가 아니라 "독립적인 판단자를 팀에 넣을 수 있는가"가 판단 기준이다.

**쓸 만한 경우:**
- 교차 검증 — 한 런타임의 결론을 다른 계열 모델이 독립적으로 반박 시도
- 2nd opinion — 설계 선택지가 갈릴 때 서로 다른 모델의 판단을 나란히 놓고 비교
- 독립 재현 — 같은 입력에 대해 서로 다른 모델이 같은 결론에 도달하는지 확인
- 보안·정합성 리뷰 — 한 모델이 만든 코드를 그 모델이 검토하면 자기 확증에 빠진다

**쓰지 말아야 할 경우:**
- 단순 생성·편집·리팩터링 — 다양성이 이득을 주지 않고 지연과 비용만 늘어난다
- 순차 파이프라인의 중간 단계 — 외부 호출이 직렬 경로에 들어가면 전체 지연이 그만큼 늘어난다
- 사용자가 외부 런타임을 언급하지 않은 경우 — **기본값은 Claude 전용 팀이다.** 멀티런타임은 명시적 요청이 있을 때만 설계한다

> 이 마지막 항목이 중요하다. 멀티런타임을 기본값으로 삼으면 모든 하네스가 외부 CLI 설치·인증에 의존하게 되고, 비용과 지연이 예측 불가능해진다.

## 2. 핵심 제약: 외부 CLI는 팀원이 될 수 없다

이 제약이 나머지 설계 전부를 결정한다.

`TeamCreate`는 **Claude Code 인스턴스**를 스폰한다. `codex`/`agy`는 Bash로 호출하는 일회성 프로세스다. 따라서 외부 런타임은:

- `SendMessage`를 **받을 수 없다** — 팀 메시지 버스에 존재하지 않는다
- `TaskCreate`/`TaskUpdate` 공유 작업 목록을 **갱신할 수 없다**
- 팀 유휴 알림·계획 승인 모드에 **참여하지 않는다**
- 호출 간 상태를 유지하지 않는다 (세션 재개 기능이 있어도 팀 컨텍스트와는 무관하다)

즉 "팀원 5명 중 2명을 codex로" 같은 구성은 **불가능하다.** 그렇게 설계하면 생성된 하네스가 실행 시점에 조용히 깨진다.

## 3. 어댑터 에이전트 패턴

해결책은 외부 런타임을 팀원이 아니라 **도구**로 취급하는 것이다.

네이티브 Claude Code 에이전트가 팀원으로 들어가고, 그 에이전트가 외부 런타임 호출을 책임진다:

```
[리더] ←→ [팀원A: 분석가]  ←→ [팀원B: codex-어댑터]  ←→ [팀원C: agy-어댑터]
  ↕            ↕                    ↕                        ↕
  └──────── 공유 작업 목록 ─────────┘                        │
                                    │                        │
                              Bash: delegate.py        Bash: delegate.py
                                    ↓                        ↓
                              [codex exec]              [agy -p]
                              읽기 전용                  읽기 전용
                                    ↓                        ↓
                              _workspace/*.md ←────────────┘
```

어댑터 에이전트의 책임:

1. **프롬프트 구성** — 팀 컨텍스트에서 필요한 정보를 모아 자기완결적 프롬프트로 만든다. 외부 런타임은 팀 대화를 볼 수 없으므로, 배경을 프롬프트에 전부 담아야 한다
2. **위임** — `scripts/delegate.py`로 외부 CLI 호출
3. **회수·검증** — 6절 규약에 따라 결과를 검증한다
4. **팀 프로토콜로 반환** — 검증된 결과를 `SendMessage`/`TaskUpdate`로 팀에 되돌린다

이 구조의 이점: 기존 팀 아키텍처를 **하나도 바꾸지 않는다.** 어댑터는 다른 팀원 입장에서 그냥 평범한 팀원이다.

**어댑터는 `general-purpose` 타입이어야 한다.** Bash 실행이 필요하므로 읽기 전용인 `Explore` 타입은 쓸 수 없다 (QA 에이전트와 같은 이유 — `qa-agent-guide.md` 참조).

## 4. 런타임 레지스트리

새 런타임을 추가할 때는 이 표에 행을 더하고 `scripts/delegate.py`의 `RUNTIMES` 딕셔너리에 항목을 하나 추가한다. 특정 CLI에 맞춘 분기를 어댑터 스킬 본문에 넣지 마라 — 런타임이 늘어날 때마다 모든 스킬을 고쳐야 한다.

| 런타임 | 비대화형 호출 | 결과 회수 | 구조화 출력 | 샌드박스(읽기 전용) |
|---|---|---|---|---|
| `claude` | 네이티브 Team/Agent | 네이티브 | — | — |
| `codex` | `codex exec "…"` | `-o <file>` | `--output-schema <file>` | `--sandbox read-only` |
| `agy` | `agy -p "…"` | stdout | `--json-schema <file>` | `--sandbox` |

**모델 계열 확인:** 런타임 이름과 실제 모델은 다르다. 예를 들어 `agy`는 `--model`로 Gemini·Claude·GPT-OSS 계열을 모두 태울 수 있다. **모델 다양성이 목적이라면 런타임이 아니라 모델을 기준으로 고른다.** `agy --model claude-*`를 쓰면서 "다양성을 확보했다"고 하면 자기기만이다.

가용 모델은 런타임이 직접 알려준다 (`agy models`, `codex --help`). 하네스 설계 시 이 목록을 확인하고, 확인 없이 모델명을 추측해 하드코딩하지 마라.

## 5. `delegate.py` 사용법

런타임마다 호출 문법·결과 회수 방식·샌드박스 플래그가 다르다. 어댑터가 매번 이 차이를 직접 다루면 같은 코드를 반복 작성하게 되므로, 스킬에 번들된 스크립트를 쓴다.

```bash
python ${CLAUDE_PLUGIN_ROOT}/skills/harness/scripts/delegate.py \
  --runtime codex \
  --prompt-file _workspace/prompts/02_review.txt \
  --out _workspace/02_reviewer@codex_findings.md \
  --cwd . \
  --timeout 600
```

| 인자 | 설명 |
|---|---|
| `--runtime` | `codex` \| `agy` (레지스트리에 등록된 것) |
| `--prompt-file` | 프롬프트 파일 경로. **인자가 아닌 파일로 넘긴다** — 긴 프롬프트의 셸 이스케이프와 인자 길이 제한을 피한다 |
| `--out` | 결과 기록 경로. 런타임별 회수 방식 차이를 스크립트가 흡수한다 |
| `--cwd` | 외부 런타임의 작업 루트 |
| `--timeout` | 초 단위 (기본 600) |
| `--model` | 모델 지정 (선택) |
| `--schema` | JSON Schema 파일 — 구조화 출력 강제 (선택) |
| `--dry-run` | 실행하지 않고 조립된 명령줄만 출력. 샌드박스 플래그 검증용 |
| `--allow-writes` | 쓰기 권한 부여. **기본은 읽기 전용** — 7절 참조 |

**종료 코드는 3분류로 정규화된다:**

| 코드 | 의미 | 어댑터의 조치 |
|---|---|---|
| `0` | 성공 | `--out` 을 읽어 검증으로 진행 |
| `2` | 타임아웃 | **1회 재시도할 가치가 있다.** 부분 출력이 있으면 `--out` 에 기록됨 |
| `3` | 런타임 오류 (CLI 부재·인증 실패·비정상 종료·빈 응답·인자 오류) | **재시도해도 같은 결과다.** 즉시 누락으로 처리 |

이 구분이 있어야 어댑터가 "재시도할 것"과 "포기할 것"을 판단할 수 있다. 종료 코드를 뭉뚱그리면 CLI가 설치되지 않은 상태에서 무의미한 재시도를 반복하게 된다.

## 6. 결과 회수·검증 규약

**외부 런타임의 출력은 신뢰할 수 없는 입력으로 취급한다.** 팀원이 보낸 메시지와 달리, 외부 런타임 출력은 형식 보장이 없고 프롬프트를 오해했을 수 있으며 아예 비어 있을 수도 있다.

어댑터는 반환 전에 다음을 확인한다:

1. **종료 코드 분기** — 위 표대로. `2`는 1회 재시도, `3`은 즉시 누락 처리
2. **형식 검증** — 기대 형식(JSON Schema, 섹션 구조 등)에 맞는지 확인한다. `--schema`를 쓴 경우에도 런타임이 스키마를 무시할 수 있으므로 회수 후 재확인한다
3. **내용 온전성** — 요청한 항목이 실제로 채워졌는지 확인한다. "분석을 수행할 수 없습니다" 같은 거절 응답도 종료 코드 0으로 돌아온다
4. **출처 명시** — 결과를 팀에 반환할 때 어느 런타임·어느 모델의 산출물인지 반드시 병기한다. 출처가 지워지면 교차 검증의 의미가 사라진다

**실패 시 처리는 SKILL.md Phase 5-2 규약을 따른다:** 1회 재시도 후 재실패하면 해당 결과 없이 진행하고, **최종 보고서에 누락을 명시한다.** 외부 런타임이 응답하지 않았다는 사실을 조용히 감추면, 사용자는 3개 모델의 합의를 본 것으로 착각한다.

**상충하는 결과는 삭제하지 않는다.** 런타임 A와 B의 결론이 다르면 양쪽을 출처와 함께 병기한다. 불일치 자체가 교차 검증의 핵심 산출물이다 — 한쪽을 임의로 채택하면 다양성을 확보한 의미가 없어진다.

## 7. 읽기 전용 원칙

**외부 런타임에는 기본적으로 쓰기 권한을 주지 않는다.** `delegate.py`가 `codex`에는 `--sandbox read-only`를, `agy`에는 `--sandbox`를 자동으로 건다.

이유:

1. **동시 수정 충돌** — 여러 런타임이 같은 워킹트리를 고치면 서로의 변경을 덮어쓴다. 팀 모드에서는 병렬 실행이 기본이므로 실제로 발생한다
2. **추적 단절** — 어느 런타임이 무엇을 바꿨는지 구분할 수 없게 된다. 문제가 생겼을 때 원인을 좁힐 수 없다
3. **검토 없는 반영** — 외부 런타임의 판단이 검토 없이 코드에 반영된다. 교차 검증을 하려고 도입했는데 검증 단계를 건너뛰는 셈이다

**따라서 역할을 분리한다:** 외부 런타임은 **분석·검토·제안**만 하고, 파일 수정은 **Claude Code가 단일 진입점으로** 수행한다. 어댑터가 회수한 제안을 팀이 검토한 뒤, 네이티브 에이전트가 적용한다.

`--allow-writes`가 존재하지만, 오케스트레이터가 이를 쓰려면 위 세 가지 위험을 어떻게 통제할지 명시해야 한다. 기본값을 뒤집는 것은 설계 결정이지 편의 옵션이 아니다.

## 8. 비용·지연

**외부 호출 1건 = 완전한 에이전트 실행이다.** 도구 호출 한 번이 아니라, 별도 모델이 전체 작업을 수행하는 비용이 든다.

- 어댑터를 `run_in_background`로 병렬화해도 **전체 지연은 가장 느린 외부 런타임에 묶인다**
- `agy`의 print 모드 기본 타임아웃은 5분이다. `delegate.py`는 기본 600초를 쓰되, 작업 성격에 맞게 `--timeout`을 조정한다
- 팀 크기 가이드라인(SKILL.md Phase 5-3)에 어댑터도 포함해 센다. 어댑터 2개를 추가하는 것은 팀원 2명을 추가하는 것과 같은 조율 비용이 든다

**오케스트레이터는 멀티런타임 사용 시 예상 외부 호출 횟수를 사용자에게 미리 알린다.** 교차 검증 대상이 10건인데 런타임 2개를 붙이면 외부 호출이 20회다.

## 9. 어댑터 에이전트 정의 템플릿

`agent-design-patterns.md`의 "에이전트 정의 구조"를 따르되, `## 위임 프로토콜` 섹션을 추가한다.

```markdown
---
name: {runtime}-adapter
description: {런타임}에 {작업 유형}을 위임하고 결과를 회수·검증해 팀에 반환한다.
model: opus
---

## 핵심 역할

{런타임}을 독립 판단자로 활용해 {작업}에 대한 외부 관점을 확보한다.
직접 판단하지 않고, 위임·회수·검증·전달에 집중한다.

## 작업 원칙

- 외부 런타임은 팀 대화를 볼 수 없다. 프롬프트는 자기완결적으로 작성한다
- 결과를 요약·윤색하지 않는다. 원문을 보존하고 출처를 병기한다
- 다른 팀원의 결론에 맞추려고 외부 결과를 조정하지 않는다.
  불일치는 그대로 보고한다 — 그것이 이 에이전트의 존재 이유다

## 위임 프로토콜

**런타임:** {codex | agy}
**모델:** {지정 시}
**권한:** 읽기 전용 (파일 수정 금지)

1. 프롬프트를 `_workspace/prompts/{phase}_{작업}.txt` 에 작성한다
2. 위임:
   ```bash
   python ${CLAUDE_PLUGIN_ROOT}/skills/harness/scripts/delegate.py \
     --runtime {runtime} \
     --prompt-file _workspace/prompts/{phase}_{작업}.txt \
     --out _workspace/{phase}_{agent}@{runtime}_{산출물}.md \
     --cwd . --timeout 600
   ```

## 산출물 파일명 규약

멀티런타임 하네스는 `_workspace/` 파일명에 런타임을 남긴다:

```
{phase}_{agent}@{runtime}_{artifact}.{ext}

예: 02_reviewer@codex_findings.md
    02_reviewer@agy_findings.md
    03_synthesizer@claude_merged.md
```

출처가 파일명에서 지워지면 나중에 어느 결론이 어느 모델에서 나왔는지 복원할 수 없다. 교차 검증 결과를 사후 감사하려면 이 규약이 필요하다.
